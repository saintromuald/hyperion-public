# Cosmonarchy on Hyperion — the port plan

Branch `cosmonarchy` of `saintromuald/hyperion-public` (forked from `pre-release`,
commit `f0f0093b`): a **separate version** of the engine for the long test
campaign of porting **Cosmonarchy BW** (the-no-frauds-club's 1.16.1
total-conversion, as the user's *Plus* build plays it) onto Hyperion as a
**toggleable mod**. When it is functional we merge it back into the release
line.

The mod itself is `engine/mods/cosmonarchy/` — the engine's mod framework
(`docs/mod-data.md`) makes it an ordinary mod: the Mods screen (or `--mod
cosmonarchy`) turns it on, the data loads over the vanilla tables, games
started with it have the Cosmonarchy types, and a game without it is untouched.

## What Cosmonarchy is made of (the 100% inventory)

The mod runs on a patched 1.16.1 exe with QDP plugins, and its data is a
Samase work tree (`mpq/`). Source of truth for this port: the local
plus-prerelease install (`~/Games/cosmonarchy/prefix/drive_c/Cosmonarchy/
Prerelease/`), which is what we actually play.

## The solved formats (write-up for whoever continues)

`engine/tools/cmport/cmport.py` documents and implements these; summary:

- `arr/<table>.datex` = the **full extended table**, column-major, each column
  one file region of `rows x width`. Rows/widths: units 3000x99, weapons
  1001x42, flingy 1000x15, sprites 2000x7, images 5000x38, orders 500x23
  (weapon widened to u16), techdata 100x19, upgrades 100x21, sfxdata 20000x9,
  portdata 1003x12, mapdata 65x4. Widths came from Hyperion's own
  `gUnitsArrayDataTbl` descriptors (`engine/src117/gen/data117.cpp`) and the
  mod's GPTP DatExt (`~/Projects/gptp-fork/DatExtend/datext.cpp`), and every
  table is validated by its exact byte size.
- `samase/*_ext.txt`: `#####<table>_<row>` blocks, `key: value` fields, applied
  after the datex. `config.ini` `data_rewrite = (unit, field, row, value)`
  applied last.
- Cross-references are remapped to record names past each table's 1.17 rows;
  the "none" markers (unit 228-232, weapon 130, order 189, tech 44, upgrade 61)
  stay numeric.
- Reference check: `cmport.py tables` decodes everything and diffs unit costs
  against `~/Games/cosmonarchy/CMBW-reference.txt` (585/588 exact; the 3
  differences are Plus-build balance changes vs the Release reference — rows
  93, 630, 651 — expected, not bugs).

## Validation

The engine builds on this branch and `Hyperion.exe --mod-check cosmonarchy`
**plays with 0 errors** (5355 warnings, all "the mod's folder does not have"
media files — sounds, portraits — which the art step provides). 663 units,
324 weapons, 742 flingy, 1224 sprites, 2536 images, 190 orders, 55 techs,
67 upgrades, 4679 sounds, 339 portraits load.

Loader quirks the converter works around (engine-side, worth fixing when the
port matures):
- a new record's `base` cannot name an edit's record — the converter bases
  new records on original row numbers;
- the images' overlay columns take numbers only, and ids past 1.17's must be
  the loader's assigned ids (name-sorted) — the converter emits those;
- the mod's "no order" (0xFFFF) maps to the original's 189.

## Workflow

```
python engine/tools/cmport/cmport.py tables        # decode + verify
python engine/tools/cmport/cmport.py gen           # write data/types.json
Hyperion.exe --mod-check cosmonarchy               # loader-level validation
Hyperion.exe --mod cosmonarchy                     # play it
```

## Next milestones (in order)

1. ~~**Graft format** (tech trees + buttons)~~ — done: `requires`/`use_requires`
   from the four requirement grafts and `cards` from `Buttons.graft` (the
   sets array is positional; action ids index GPTP's `button_act_funcs`).
   Left for the engine step: morph buttons, research buttons for edited techs
   on cards the original does not research them on, add-on requirements, and
   the spells GPTP handles without orders. `Orders.graft` (per-order
   requirement scripts) also lands with the engine step.
2. **iscript.txt** — the mod ships `.txt` iscript forms for some; write the
   binary->text converter for the rest.
3. **Art pipeline** — copy GRPs/pcxs/smk/wav into the mod's data folder from
   the install (player-side), wire paths.
4. **Engine: gameplay-mod support** — main button for a data mod, extended
   tilesets, mod strings for labels.
5. **QoL port — LAST, and slow.** The GPTP/Plus plugin features (saturation
   overlays, Tab cycling, F11 HUD, idle-worker key, larva picker, custom
   triggers, Lua melee AI, the game modes). Some are already in Hyperion
   itself (anti-meta is a mutator; the engine has extended selections,
   zoom, HUD designs), so each item gets a "already present?" check first.
   This is the hardest part to get right and is deliberately scheduled at
   the end, one feature at a time, with the test campaign behind it.
6. **Test campaign** — replay-free, headless matches against the reference
   install, then merge back to `pre-release`/release.
